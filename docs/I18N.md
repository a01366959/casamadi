# Internationalization (i18n) Standards

## Overview

Casamadi is a Spanish-first application serving hotel staff in Mexico and other Spanish-speaking countries. All UI text must be in Spanish by default.

## Core Principles

1. **Spanish First**: All new UI text is in Spanish
2. **English Secondary**: Build an English version only after Spanish is complete
3. **Centralized**: All strings stored in `apps/web/src/lib/spanish.ts`
4. **Consistent**: Use the `ES` constant everywhere; never hardcode UI strings
5. **Discoverable**: When adding new text, immediately add it to `spanish.ts`

## Current Implementation

### Translation File

All Spanish strings live in a single file: **`apps/web/src/lib/spanish.ts`**

```typescript
export const ES = {
  nav: { dashboard: "Dashboard", ... },
  dashboard: { title: "Dashboard", ... },
  auth: { email: "Correo electrónico", ... },
  common: { room: "Habitación", ... },
}
```

### Usage Pattern

**In any component:**

```typescript
import { ES } from "@/lib/spanish"

export function MyComponent() {
  return (
    <div>
      <h1>{ES.dashboard.title}</h1>
      <button>{ES.common.save}</button>
    </div>
  )
}
```

**Never do this:**
```typescript
// ❌ WRONG - hardcoded string
<button>Guardar</button>

// ❌ WRONG - English fallback
<button>Save</button>

// ✅ CORRECT - use ES constant
<button>{ES.common.save}</button>
```

## Adding New Strings

When building a new page or component:

1. **Identify all UI text** that users see
2. **Add to `ES` object** in the correct category (nav, dashboard, auth, common, etc.)
3. **Import `ES`** in your component
4. **Reference via `ES.category.key`**

### Example: Adding "Nuevo Pedido" button

```typescript
// Step 1: Add to spanish.ts
export const ES = {
  // ...
  orders: {
    newOrder: "Nuevo Pedido",
    pending: "Pendiente",
  },
}

// Step 2: Use in component
import { ES } from "@/lib/spanish"

export function OrdersPage() {
  return <button>{ES.orders.newOrder}</button>
}
```

## Future: English Version

When ready to add English (after MVP in Spanish):

1. Create `apps/web/src/lib/english.ts` with identical structure
2. Add language detection via Next.js i18n middleware or React context
3. Switch between `ES` and `EN` based on user preference
4. Store preference in Supabase `users` table

**Do not start this until Spanish MVP is complete.**

## Structure by Category

### `nav`
Navigation and menu items: dashboard, conversations, orders, tasks, etc.

### `dashboard`
Dashboard page: active conversations, pending orders, pending tasks, escalations, recent orders/tasks, etc.

### `auth`
Authentication pages: email, password, sign in, errors, etc.

### `common`
Frequently used words: room, items, loading, error, save, cancel, etc.

### `(add more as needed)`
conversations, orders, tasks, orders, settings, admin, etc.

## Naming Convention

- **Keys**: camelCase (e.g., `activeConversations`, `invalidCredentials`)
- **Values**: Proper Spanish sentences with capitals and punctuation
- **Scope**: Organize by feature/page (nav, dashboard, auth, etc.)

```typescript
export const ES = {
  common: {
    room: "Habitación",           // Simple nouns
    loading: "Cargando...",       // Actions with ellipsis
    viewAll: "Ver todo",          // Action phrases
    since: "desde hace",          // Prepositions for context
  },
  dashboard: {
    activeConversations: "Conversaciones Activas",  // Descriptive titles
    pendingOrders: "Pedidos Pendientes",
  },
}
```

## Validation Checklist

Before marking a page/component complete:

- [ ] All visible text references `ES.*` constant
- [ ] No hardcoded English or Spanish strings in JSX
- [ ] New strings added to `spanish.ts` in correct category
- [ ] Strings are grammatically correct (verb tense, gender, etc.)
- [ ] Component imports `ES` from `@/lib/spanish`

## Error Messages

All error messages from backend/API responses must be translated:

```typescript
// DO NOT return English error from API
const error = "Invalid login credentials"

// Instead, map to Spanish in component:
if (error.includes("Invalid login")) {
  return ES.auth.invalidCredentials
}
```

See `login-form.tsx` for example error mapping.
